# OctoTools baseline

[OctoTools](https://github.com/octotools/octotools) (Lu et al., 2025) is the strongest baseline in the MapAgent
paper. It is a flat (single-layer) planner–executor agent: at every step it analyses the memory, selects one tool,
writes the Python command that calls the tool, executes it and decides whether to stop.

For a fair comparison this copy uses:

- the same map tools as MapAgent (`Trip_Tool`, `Directions_Tool`, `Nearby_Tool`, `POI_Tool` are thin wrappers
  around `mapagent/map_tools/tools.py`) plus `Generalist_Solution_Generator_Tool` (and `Image_Captioner_Tool` for
  MapEval-Visual);
- MapAgent's data loader, answer extraction and result format, so `evaluate.py` scores both systems in the same way.

```bash
pip install -r requirements.txt -r baselines/octotools/requirements.txt
python baselines/octotools/solve.py --benchmark mapeval_api --model gpt-4o-mini --limit 5
python evaluate.py results/mapeval_api/octotools_gpt-4o-mini
```

`solve.py` accepts the data options of `run.py` (`--benchmark`, `--tasks`, `--data_root`, `--split`, `--limit`,
`--use_context`, ...) plus `--enabled_tools`, `--max_steps` (default 10) and `--max_time` (seconds per question,
default 300). The LLM backend is configured with the same environment variables as MapAgent (`OPENAI_API_KEY`,
`OPENAI_BASE_URL`, `MAPAGENT_LLM_PROVIDER`, `AZURE_OPENAI_*`) and the map tools need `GOOGLE_MAPS_API_KEY`.
Models without native structured outputs (e.g. GPT-3.5-Turbo, Qwen-2.5-72B) are supported through JSON parsing.

The executor runs the Python commands generated by the LLM with `exec`; use an isolated environment.
